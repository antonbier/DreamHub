# frontend/

The web UI: Vue 3 (Composition API, `<script setup>`), TypeScript, Vue Router, Pinia, Tailwind CSS and vue-i18n. Built as static files and embedded into the Go backend via `go:embed` — see [`../backend/README.md`](../backend/README.md#frontend) and [`../backend/internal/webui`](../backend/internal/webui).

Mirrors the hub structure (`../CONCEPT.md`): a core shell (sidebar, top bar, dashboard, settings) plus one route per hub, built out as each hub itself is built (`../ROADMAP.md`). Visual and interaction decisions — colors, type, spacing, breakpoints, components — follow [`../DESIGN.md`](../DESIGN.md); that file is the source of truth, not this code.

## Running

```sh
npm install
npm run dev
```

Opens on `http://localhost:5173` and proxies `/api` to a backend running separately on port 8080 (`go run ./cmd/dreamhub` in `../backend`) — see `vite.config.ts`. This gives hot reload; nothing here works standalone without a backend, mock or real, to talk to.

```sh
npm run build
```

Type-checks (`vue-tsc -b`) and builds straight into `../backend/internal/webui/dist` (see `vite.config.ts`, `outDir`) — that's what `go build`/`go run` in the backend then embeds and serves. `npm run build:skip-check` skips the type-check for a faster iteration loop; CI and releases should use the full `build`.

## Conventions

- **No external requests at runtime** (`../PRINCIPLES.md`): fonts (Source Sans 3, Source Code Pro — `@fontsource/*`) and every script/stylesheet are bundled, nothing loads from a CDN or Google Fonts. Verify with the browser's network tab against an offline network if in doubt.
- **i18n everywhere user-facing**: no hardcoded UI strings. Locale files are `src/locales/{de,it,en}.json`; `en` is the fallback (`src/i18n/index.ts`). Backend status/problem codes (`internal/status`, `internal/hub`) are translated by `src/composables/useProblem.ts` — the backend's `Fix` values already carry their own `fix.` prefix, `Code` values don't (they're nested under `problem.` in the locale files); see that file's comments before changing either.
- **RTL-ready**: Tailwind's logical-property utilities only (`ps-`/`pe-`, `ms-`/`me-`, `start-`/`end-`, `text-start`/`text-end`, `border-s`/`border-e`) — never `left`/`right`, `ml-`/`mr-`, etc.
- **Design tokens** are CSS custom properties in `src/style.css` (`--dh-*`), mapped into Tailwind's theme in `tailwind.config.js`. Appearance (dark/light/system) is applied as `data-theme` on `<html>` by `src/stores/preferences.ts`, not Tailwind's `dark:` media-query variant.
- **Custom breakpoints** (`below-lg`/`below-md`/`below-sm`, i.e. `max-width` queries) match `../DESIGN.md`'s layout breakpoints exactly (1180/900/640px) — see `tailwind.config.js`. They replace Tailwind's default `sm`/`md`/`lg`/… scale on purpose, so a component doesn't reach for those by habit.
- **A hub view without a backend implementation yet is a real placeholder, not a mock**: `HubView.vue` shows that hub's actual live status and problems from `GET /api/v1/navigation`, translated, with a fix hint — it just doesn't have the hub's own screens yet. Don't invent fake data to make a screen look more finished than the backend behind it.
- **A section's settings label and its fields' labels collide as i18n keys** (`settings.general` vs. `settings.general.language`) — see `src/composables/useSettingsText.ts`'s comment before adding a section or changing how labels are looked up.
- **Settings and the dashboard save directly** (no preview/apply — PRINCIPLES.md's exception for DreamHub's own state), but saving `general.language`/`appearance`/`navLabels` from the settings page must also update the live `preferences` store, or the UI would only pick up the change after a reload; see `SettingsSectionCard.vue`'s `syncPreferences`.
- **The app manages Basic Auth itself, not the browser** — see `src/api/authState.ts`'s comment for why (only `/api/v1/*` sits behind auth, not the SPA shell, so a plain 401 never triggers the browser's native credentials prompt). `LoginScreen.vue` collects a username/password, `GET /api/v1/whoami` confirms them, and every request after that carries an `Authorization` header built from what's stored in `sessionStorage`. A 401 from *any* endpoint drops the stored credentials and falls back to the login screen (`client.ts`) — unless its code is `profile_required`/`profile_session_invalid`: then the door is open and `ProfilePicker.vue` asks which profile this device is (docs/PROFILES_PLAN.md). The profile's session token lives in `localStorage` and goes out as `X-DreamHub-Profile` with every request (`authHeaders()`). `useAuth().can(permission)` leaves out buttons the server would refuse; the router sends a viewer away from admin-only pages.
- **Nothing here fabricates data it can't back up.** `NotificationsBell.vue`'s "current issues" are hub problems already in the navigation store plus a clock-skew check, live-computed, not persisted; its "recent activity" is the real (if partial) `hub.statusChanged` history the backend now writes — a full event-bus-backed inbox covering every hub action is still open (ROADMAP.md). `SearchPalette.vue` merges local page matches with `GET /api/v1/search` for hub-contributed content (TimerHub is the first real provider); more hubs join as they implement the contract.

## Layout

- `src/main.ts` — mounts the app with Pinia, Vue Router and vue-i18n.
- `src/App.vue` — the core shell: sidebar + top bar + status strip around the routed view; loads preferences and navigation once at startup. Gated by auth — renders `LoginScreen.vue` instead of the shell until `useAuth.ts`'s `check()` confirms `GET /api/v1/whoami`.
- `src/router/` — one route per hub path (mirrors `backend/internal/hub/v1.go`), `/` (dashboard), `/settings/:tab?` and `/onboarding`. A global guard sends every route to `/onboarding` until `lib/onboarding.ts`'s local flag says it's run once.
- `src/stores/` — Pinia stores: `preferences` (language/appearance/navLabels, backed by `GET`/`PATCH /api/v1/settings`), `navigation` (sidebar contents), `ui` (transient state — currently just the mobile drawer's open/closed).
- `src/api/` — a small typed fetch wrapper (`client.ts`, CSRF header on mutating requests, Basic Auth header, the backend's error envelope), the Basic Auth credential store (`authState.ts`), and hand-written types mirroring the backend's JSON shapes (`types.ts`).
- `src/composables/useFocusTrap.ts` — keeps Tab inside a modal and closes it on Escape; every modal uses it (DESIGN.md, Interaction).
- `src/composables/` — `useProblem.ts` (translates `status.Problem` values), `useSettingsText.ts` (section/field/option/error-code labels for the settings menu), `useSettingsForm.ts` (drafts, dirty tracking, per-section save against `GET`/`PATCH /api/v1/settings`), `useDashboard.ts` (loads and persists the dashboard layout against `GET`/`PUT /api/v1/dashboard`), `useAuth.ts` (login/logout/check against `GET /api/v1/whoami`), `usePlexText.ts` (PlexHub's item texts: details line, episode code, formats, progress), `useDeviceStatus.ts` (shared, single-fetch clock-skew + reachability + issue count for `StatusStrip.vue` and `NotificationsBell.vue`).
- `src/lib/` — small framework-free helpers: `clock.ts` (box-vs-browser clock skew), `onboarding.ts` (the "has the wizard run" flag, `pwa.ts` (service worker registration and the install prompt)).
- `public/` — copied as-is into the build: `manifest.webmanifest`, `sw.js` (the service worker — shell only, never `/api/*`), `icons/` (SVG sources plus PNGs rendered by `art/render-icons.mjs`; re-run it after changing an SVG).
- `src/components/` — `AppSidebar.vue`, `AppTopBar.vue`, `StatusStrip.vue` (DESIGN.md's status line), `DropdownMenu.vue`, `Icon.vue` (a small self-drawn icon set — no icon font/CDN), `LoginScreen.vue`, `UnreachableScreen.vue` (no answer at all at startup — not a login problem), `profiles/` (`ProfilePicker.vue` — "who's watching?", `ProfileAvatar.vue`, `ProfilesPanel.vue` + `ProfileForm.vue` — managing profiles on the settings tab "Profiles", `MyPinPanel.vue` — every profile's own PIN), `SearchPalette.vue` (Cmd/Ctrl+K or `/`), `NotificationsBell.vue`, `channels/` (`BouquetDraftEditor.vue` — ChannelHub's bouquet editor: draft, review, apply; `useChannelChange.ts` — a channel plan's changes in words), `ErrorText.vue` (a failure in everyday words with "Details", `composables/useFriendlyError.ts`); `settings/` (`SettingsSectionCard.vue`, `SettingsFieldInput.vue` — the generic, schema-driven form; `ApiTokensPanel.vue` — the one hand-built exception, since tokens are a list of resources, not a schema field; `PushPanel.vue` and `InstallPanel.vue` — help panels placed after their section; `BackupPanel.vue` — backup & restore on the System tab; `PlexPanel.vue` — Plex sign-in and library choice); `plex/` (`PlexItemCard.vue`, `PlexItemRow.vue`, `PlexItemDialog.vue`, `PlexWatchedPreview.vue` — PlexHub's tile, row, details and season preview); `dashboard/` (`DashboardTileFrame.vue` — chrome shared by every tile; `TimersUpcomingTile.vue`, `HubsStatusTile.vue` — the v1 built-in tiles, reusing `GET /api/v1/timers` and `GET /api/v1/hubs`; `RecentRecordingsTile.vue`, `LiveTvTile.vue` ("Now on TV") and custom tiles' poster rows for the viewers' start page — `DashboardView.vue` with `?template=1` is where an admin designs it); `onboarding/` (`OnboardingStepFrame.vue` — shared chrome; one component per wizard step).
- `src/components/PlanPreview.vue` — the shared inline preview every mutating action shows (eyebrow, summary slot, the plan's warnings, one confirm + one cancel); `src/composables/usePlanError.ts` turns a failed plan/apply into a message, including the box's own text for `box_rejected`. `src/components/timers/` — `TimerRow.vue` (one timer, with its delete preview). `src/components/media/` — `RecordingRow.vue` (one recording: inline rename with the before → after file list, move to trash), `TrashPreview.vue` (restore / delete-for-good preview). `src/lib/format.ts` — `formatBytes`, decimal units through `Intl`, the one way sizes are shown. `dashboard/TimersConflictsTile.vue` — the "Conflicts" tile. `dashboard/CustomTile.vue` and `dashboard/CustomTileBuilder.vue` — custom tiles and their builder dialog; `src/composables/useViewText.ts` describes a view's criteria in one line.
- `src/components/control/` — ControlHub's remote (`RemotePad.vue`), the live picture (`ScreenView.vue`) and the side panel with both that any page can open (`RemotePanel.vue`, mounted once in `App.vue`); shared state (panel open, standby, keys sent) in `src/stores/remote.ts`, key codes and keyboard mapping in `src/lib/remoteKeys.ts`.
- `src/components/enrich/` — `PosterImage.vue` (a poster fetched with the auth header, object URLs shared per session), `RatingBadge.vue`, `EnrichDetails.vue` (poster + year/genres/rating + overview, renders nothing without data); `src/stores/enrich.ts` batches every title a screen asks about into `POST /api/v1/enrich/lookup` calls and remembers the answers.
- `src/views/SeriesDetailView.vue` — one tracked series (`/series/:id`), linked from `SeriesHubView.vue`.
- `src/components/system/SelfTestPanel.vue` — the box self-test on System → Diagnostics (admin only, hidden on a 403): run, the rated checks, the captured answers as a zip.
- `src/components/admin/ServicesPanel.vue` — AdminHub's service status: units with their state, Restart/Start through `PlanPreview`, "Logs" emits the unit for the log viewer's filter.
- `src/components/dashboard/NowPlayingTile.vue` — "Now on the box" (`GET /api/v1/control/current`) with channel up/down, mute and the remote panel.
- `src/views/RadioHubView.vue` — RadioHub (`/radio`): stations with now/next, the one playing on top, Play on the box (ControlHub's zap), radio recordings, and the shared `ProgrammeDialog` (`plain`) for Record. Station logos reuse `guide/ChannelLogo.vue` with `source="radio"`.
- `src/views/StreamHubView.vue` — StreamHub (`/stream`, "Live TV"): the player, a bouquet's channels with now/next, "same as the TV", audio track, volume, full screen; `?recording=` plays a recording (MediaHub's "Watch in the browser") with a seek bar. Channel logos through `guide/ChannelLogo.vue` with `source="stream"`.
- `src/streaming/tsPlayer.ts` — the player: libav.js (FFmpeg in WebAssembly, `public/libav/`, see its README) demuxes the MPEG-TS and decodes MPEG-2 (deinterlaced) and MP2/AC3/AAC; H.264 goes to WebCodecs; Web Audio is the clock. The spike with measurements: `spikes/streamhub-player/`.
- `src/views/` — `TimerHubView.vue` (timers by day, delete via preview, the optional AutoTimer section), `DashboardView.vue` (tile grid, edit mode with native drag-and-drop reorder), `HubView.vue` (the shared per-hub placeholder), `SettingsView.vue` (renders every section `GET /api/v1/settings` returns on the tab the section names — no per-field list to keep in sync here; the tab order is `src/lib/settingsTabs.ts`), `OnboardingView.vue` (the wizard shell), `PlexHubView.vue` (Plex library: tiles/list, series pages, watched state, play on the box), `NotFoundView.vue`.
- `src/locales/` — `de.json`, `it.json`, `en.json`.

## Known issue

`npm audit` flags a moderate advisory in `esbuild` (via Vite's dev server only — `npm run dev`'s local dev server could accept requests from an arbitrary website in a victim's browser and read the response; the production build this ships is unaffected). Fixing it needs a Vite 8 upgrade; left as-is for now since `npm run dev` only ever runs on a developer's own machine, not on the box.
